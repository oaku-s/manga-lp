# 案件保存（GAS + スプレッドシート）セットアップ手順

上から順に実行してください。所要 15〜20 分程度です。

構成は次のとおりです。共有トークンはブラウザに渡らず、Vercel の環境変数と GAS のスクリプトプロパティにだけ存在します。

```
ブラウザ  ──同一オリジン──▶  /api/projects（Vercel）  ──トークン付与──▶  GAS Web アプリ  ──▶  スプレッドシート
```

---

## 1. スプレッドシートを作る

1. Google ドライブで新しいスプレッドシートを作成する
2. 名前は任意（例：`ComicLP 案件管理`）
3. **シートの中身は空のままでよい**。`案件` シートとヘッダー行は初回アクセス時に自動生成される

## 2. GAS プロジェクトを紐付ける

1. そのスプレッドシートで「拡張機能」→「Apps Script」を開く
2. プロジェクト名を付ける（例：`ComicLP 案件API`）
3. 「プロジェクトの設定」（左の歯車）を開き、**スクリプトID** をコピーしておく

> スクリプトIDはこの後の clasp 設定と、こちらへの共有に使います。

## 3. clasp でコードを push する

リポジトリの `gas/` にコードが入っています。

```bash
npx clasp login
```

`gas/.clasp.json` を作ります（`gas/.clasp.json.example` をコピーして `scriptId` を差し替え）。

```bash
cp gas/.clasp.json.example gas/.clasp.json
```

`scriptId` に手順2でコピーした値を入れてから、

```bash
npx clasp push --project gas/.clasp.json
```

Apps Script エディタを再読み込みし、`projects.gs` が入っていることを確認してください。

> `.clasp.json` は `.gitignore` に入れてあります。スクリプトIDは秘密情報ではありませんが、環境ごとに変わるためコミットしません。

## 4. 共有トークンを決めてスクリプトプロパティに入れる

推測できない十分に長い文字列を用意します（32文字以上を推奨）。

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Apps Script エディタで「プロジェクトの設定」→「スクリプト プロパティ」→「スクリプト プロパティを追加」

| プロパティ | 値 |
| --- | --- |
| `SHARED_TOKEN` | 生成した文字列 |

**この値は手順6でも使うので控えておいてください。**

## 5. ウェブアプリとしてデプロイする

1. エディタ右上「デプロイ」→「新しいデプロイ」
2. 種類の選択（歯車）→「ウェブアプリ」
3. 設定
   - 説明：任意（例：`v1 案件API`）
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」→ 初回は承認画面が出るので、自分のアカウントで許可する
5. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/.../exec`）をコピー

> 「アクセスできるユーザー：全員」は、Vercel のサーバーから呼ぶために必要です。URL を知られても、トークンが一致しないリクエストは `unauthorized` で拒否されます。

動作確認として、ブラウザでそのURLを開くと `{"ok":true,"sheet":"案件"}` が返ります。

## 6. Vercel に環境変数を設定する

Vercel ダッシュボード → プロジェクト `manga-lp` → Settings → Environment Variables

| 変数名 | 値 | 対象環境 |
| --- | --- | --- |
| `GAS_WEBAPP_URL` | 手順5のウェブアプリURL（`/exec` まで） | Production / Preview / Development |
| `GAS_SHARED_TOKEN` | 手順4のトークン | Production / Preview / Development |

保存後、**再デプロイが必要です**（環境変数は既存のデプロイには反映されません）。Deployments から最新のものを Redeploy してください。

## 7. 動作確認

1. ツールを開く（https://manga-lp-gyvq.vercel.app/ ）
2. 最上部に「案件」カードが出ている
3. フォームに何か入力し、保存方法「新規案件として保存」→「この案件を保存」
4. 「新しい案件 P-0001 として保存しました」と表示される
5. スプレッドシートに `案件` シートができ、1行追加されている
6. ページを再読み込みし、案件セレクトから P-0001 を選んで「読み込む」→ フォームが復元される

### うまくいかないとき

| 症状 | 原因 |
| --- | --- |
| `案件保存の設定が未完了です` | 手順6の環境変数が未設定、または再デプロイしていない |
| `403 unauthorized` | 手順4のトークンと手順6の `GAS_SHARED_TOKEN` が不一致 |
| `GASの応答がJSONではありません` | 手順5のアクセス設定が「全員」になっていない（ログイン画面のHTMLが返っている） |
| 案件一覧が空のまま | まだ1件も保存していない。エラーが出ていなければ正常 |

---

## 変更したコードを反映するには

```bash
npx clasp push --project gas/.clasp.json
```

push しただけでは公開中のウェブアプリは変わりません。「デプロイ」→「デプロイを管理」→ 対象のデプロイを編集 →「バージョン」を **新バージョン** にして「デプロイ」を押すと反映されます。

## 次段階の予定（今回は未実装）

- `生成結果` シート：生成した LP HTML や 4 コマデータを案件IDで紐付けて保存
- `修正履歴` シート：**対象セクション**を列に持ち、どのセクションが何回書き直されたかを集計できるようにする
- Drive：案件ごとのフォルダを作り、フォルダIDを `案件` シートの列として追加

`案件` シートの読み書きはヘッダー名で解決しているため、列を末尾に足しても既存のコードと既存の行は壊れません。
